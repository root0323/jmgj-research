# AstroSky 복사전달 모델 개정 · 2026-10-28

사용자가 제공한 첫 연구 보고서는 기존 계산의 설계·검증 배경으로 읽었다. 그 보고서나 2007·1991년 논문을 그대로 재현하는 작업이 아니라 기존 위성광·지형·기상 입력을 유지하며 산란 계산을 교체했다. 원래의 `C²`, 일정 구름 반사율, `ms_a + ms_b*AOD` 계산은 `physics_model="legacy"`에서 이전 결과를 재현할 수 있다. 앱·설정 없는 `run_pipeline`·대화형 실행·평가 도구의 현재 경로는 `sos3d`다. 기존 연구 실행기와 매개변수의 재현성을 위해 `EnvironmentConfig()` 생성자만 legacy 기본값을 유지한다. 새 호출에서는 모델을 명시한다.

```python
config = EnvironmentConfig(physics_model="sos3d", aod=0.15,
                           cloud_fraction=0.7, cloud_base_h=1.0)
```

## 실제 바꾼 계산

`core/radiative_transfer.py`는 공간 3차원·방향 이산화·차수별 양의 산란 합을 독립 구현한다. 각 차수의 광량은 다른 방향으로 산란하거나 흡수·탈출하며 지표의 Lambert 반사도 다음 차수에 전달된다.

\[
\Omega\cdot\nabla L^{(n)}+\beta_eL^{(n)}
=\sum_s\frac{\beta_s}{4\pi}\int P_s(\Omega\cdot\Omega')L^{(n-1)}(\Omega')d\Omega',
\qquad L=\sum_{n=0}^{N}L^{(n)}.
\]

지상 광원·배경광은 경계조건이며 달의 평행광은 첫 산란의 별도 입력이다. 차수에는 지표 반사와의 결합도 포함된다. 전체 결과에 경험적 다중산란 배수를 곱하지 않는다. 광원별 수렴을 따로 검사하므로 밝은 달이 미수렴 인공광을 가리지 않는다. 최근 차수의 비율로 남은 꼬리를 추정하고 기준에 못 미치면 계산을 실패시킨다. 추정 꼬리를 최종값에 더하거나 배수로 쓰지 않는다. 이것은 MSOS-LP1의 엄밀한 오차 상한과 다르다.

방향별 위상 함수는 Rayleigh와 Cornette–Shanks를 쓴다. 좁은 전방 산란은 방향 셀 안에서 추가 적분하며, 이산 연산자의 에너지·상반성을 보정한다. 이 보정은 관측값에 맞춘 밝기 계수가 아니다. CS의 입력 `g`는 형상 매개변수이며 정확한 평균 코사인은 `3g(4+g²)/(5(2+g²))`다. 현재 기본 형상값 0.75·0.85를 API에서 측정한 에어로졸·구름 비대칭도라고 해석하지 않는다.

`core/modern_sky.py`는 실제 요청 방향으로 복사전달식을 다시 적분한다. 구름 경계 양쪽의 물질을 섞지 않고 구간별 지수 소광을 적분한다. 달의 첫 산란은 실제 각거리에서 계산하고, 유한한 달 원반도 별도로 계산하므로 피크가 방향 격자의 가장 가까운 칸으로 뭉개지거나 `1/각거리²`로 발산하지 않는다. 달의 상대 위상 계수를 lux로 오인하지 않고 V등급 상당 조도로 변환한다.

연구의 SQM-L 비교는 FWHM 20° 가우스 각도 응답으로 확산광을 적분하고 직접 달빛 응답도 더한다. 제조사 응답의 근사이며 실제 개별 기기의 교정 곡선은 아니다. 앱의 천체 방향 밝기는 측정기 시야로 평균하기 전의 분해된 하늘 복사휘도다. 이 둘을 같은 예측이라고 보고하지 않는다.

## 구름과 단위

운량은 구름 기둥을 만날 확률 `C`로 사용한다. `L=(1-C)L_clear+C L_cloudy`이며 운량을 제곱하지 않는다. 흐린 기둥에서는 공기·구름의 산란과 소광을 함께 풀고 구름 위의 대기도 유지한다. 인공광 중 구름을 한 번 이상 거친 경로에 표지를 붙여 `I_cloud_final`로 집계한다. 흐린 기둥의 인공광 전체를 구름 성분으로 부르지 않는다.

광학 두께가 있으면 사용하고, 단위가 명확한 액체 수분경로가 있으면 `tau=3*LWP/(2*rho_water*r_eff)`로 계산한다. 현재 저장 API는 구름 수분 단위를 단순 `g`로 표시하므로 임의로 `g/m²`로 간주하지 않았다. 값이 없으면 **광학 두께 10, 층 두께 1km**를 명시적인 가정으로 사용하고 1·10·30 시나리오를 별도 보존한다. 단일 산란 알베도 0.999는 산란 사건에서 흡수되지 않는 비율이며 구름 전체 반사율을 0.999로 고정한다는 뜻이 아니다. 전체 반사·투과는 수송 계산에서 결정된다.

대류운 밑면 기압은 일반적인 모든 구름 밑면의 관측값과 같지 않다. 한 끝점이 0이면 양의 기압으로 보간하지 않는다. 기존 10월 27일 보간은 0→922hPa에서 약 51hPa·19.21km를 만들었으며, 새 연구에서는 해당 입력을 무효로 보고 **2km 가정**을 기록했다. 앱의 저장 기상 경로는 필요한 기압이 없으면 기존 자료 부족 추정으로 돌아간다. 이전 원본·수치·분석 실행은 수정하지 않았다.

길이는 km, 소광·산란계수는 km⁻¹, 내부 복사휘도는 W m⁻² sr⁻¹다. 기존 DNB 변환 `1 nW/(cm² sr)=1e-5 W/(m² sr)`와 `SQM=12.59-2.5 log10(683 L)`를 유지한다. 683은 V등급 상당의 환산 관례로 쓰며 DNB와 SQM-L의 실제 분광 응답을 교정한 것은 아니다. 픽셀 면적 0.169km²·Garstang 방향 방출·지표 알베도 0.15도 입력 가정이다.

## 검증과 적용 범위

에너지·광량 수지, 위상 함수 정규화, 양의 복사휘도, Beer–Lambert 극한의 격자 세분화, 구름 경계, 성분 합, 구름 경로 표지, 진공·달 피크, 운량 선형 기대값, 미수렴 거부를 검사한다. Android/PWA는 같은 방정식을 NumPy 파면 순서로 계산하며 실제 Pyodide 번들과 네이티브 결과를 비교한다.

기본 격자는 수평 16×16·연직 비균일 격자·48방향, 광학 두께에 따른 구름층 세분화다. 기본 차수 허용값은 추정 잔여 0.5%, 최대 512차이며 초기에 수렴하면 멈춘다. 산란 차수 수렴과 공간·방향 격자 오차는 다르다. 공간 2배·96방향 시험도 연구 기록에 남긴다. 그 시험은 선택한 합성 장면에 대한 확인이며 모든 환경에서 같은 오차를 보증하지 않는다.

구름은 **독립 기둥 근사**다. 2025년 논문의 확률적 3차원 구름 형태를 그대로 구현한 것이 아니다. 실제 달 방향의 구름 가림, 구름의 수평 위치·여러 층, 상세 지형 체적 차폐, 분광·편광, 월면·기기별 응답은 해결되지 않았다. 지형은 기존 광원 방향 차폐와 직접 달빛의 지평 차폐로 근사한다. 평면 대기·유한 영역이므로 특히 지평선 가까운 결과의 한계가 크다.

10월 22일 49개·27일 33개를 모두 유지해 이전 앱 기본값과 새 계산을 비교했다. 10월 15일은 보관 전용, 26일은 황혼으로 분리했다. 새 계수를 이 82개에 최적화하지는 않았지만 모델 구조를 검토하는 데 사용한 자료이므로 **사후 비교**이며 독립 미래 검증이 아니다. 27일의 달 접근 방향처럼 새 모델의 오차가 커지는 관측도 보존한다. 정확한 MSE/RMSE·조건·예측·그래프는 [개정 연구 기록](../backend/tools/sky_brightness/research/revisions/2026-10-28_transport_physics/)과 [결과 색인](../backend/tools/sky_brightness/research/RESULTS.md)을 따른다.
