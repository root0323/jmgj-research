# AstroSky Android

Windows 앱을 유지하면서 추가한 Android 버전이다. 휴대폰·태블릿에서 같은 천체 화면, 장비 설정, 사진, 촬영 안내, 개인 기상 자료와 지역 계산을 사용한다.

## 설치와 호환

- Android 8.0(API 26) 이상, WebGL 지원과 최근 Android System WebView가 필요하다. ARM/ARM64/x86 기종으로 제한하지 않는 Java+WebAssembly APK이다.
- GitHub Release의 `AstroSky-0.8.3-Android.apk`를 기기에서 연다. Android가 요청하면 해당 다운로드 앱의 APK 설치 권한을 허용한다.
- 휴대폰·태블릿, 세로·가로 화면에 맞춰 버튼과 패널을 배치한다. 모든 제조사·기기에 대한 실제 검증을 의미하지 않는다.
- 나침반 버튼을 누르면 후면 카메라가 가리키는 하늘 방향을 따라간다. 회전 벡터 센서, 지자기 회전 벡터, 가속도+지자기 순으로 사용한다. 관측 위치의 자기편각을 보정하며 기울기·방위각을 부드럽게 적용한다. 센서가 없는 기기는 손으로 조작한다. 백그라운드에서는 센서를 해제한다.
- 동일 앱 ID와 서명 키로 새 APK를 설치하면 기존 버전에 덮어쓰며 앱 설정과 지역 저장 자료를 유지한다. 0.8.0 사용자는 이번 APK를 한 번 직접 덮어 설치한다. 0.8.1부터는 설정 창 아래의 `업데이트 확인`에서 새 버전 확인·다운로드·설치 화면 열기를 사용할 수 있다.

## 데이터와 계산

- 기존 Windows/FastAPI 서버 또는 사용자의 PC에 연결하지 않는다. 지역 계산은 기기 안의 별도 Pyodide 0.29.3 작업에서 실행한다.
- 기존 Python 연구 모델과 계수, NumPy/H5Py/Rasterio를 포함한다. Numba JIT는 같은 Python 함수로 대체한다. 기종에 따라 첫 준비와 계산 시간이 달라진다.
- 기본 별·은하수·지평 배경과 배경 분리 모델은 내장한다. DSS 등 원격 사진, 첫 지역 다운로드와 새로운 기상 조회에는 인터넷이 필요하다.
- Copernicus GLO-90 DEM과 2025년 Black Marble 앱용 타일을 관측 위치 주변만 자동 다운로드한다. NASA 계정은 필요 없으며 H5의 크기·SHA-256을 검증한다.
- 원본 압축 타일은 앱 전용 파일 폴더에 저장한다. 다시 선택하면 재사용한다. 전체 세계 데이터는 APK에 포함하지 않는다.
- GDAL/WASM의 Deflate 제약 때문에 DEM은 계산 작업의 임시 메모리에서만 무압축 float32 TIFF로 바꾼다. 픽셀·해상도·원래 PixelIsPoint/Area 좌표·결측값을 유지한다. 디스크 원본은 변경하지 않는다. 임시 지역 작업은 두 곳까지 유지한다.
- 기상은 IndexedDB, 장비·설정은 WebView 저장소, 사용자가 넣은 배경은 기기 CacheStorage에 저장한다. 개인 Meteoblue 키는 입력 후 현재 세션에서만 사용한다. 로그·앱 파일·Git에 넣지 않는다.
- Android 원점은 `https://appassets.androidplatform.net`으로 고정한다. 네이티브 메시지는 해당 원점의 최상위 프레임으로 한정하고 외부 링크는 브라우저로 연다. HTTPS 제공자·자료 경로를 제한한다. 위치 권한은 현재 위치 요청 시에만 묻는다.

## 빌드

JDK 17, Gradle 8.11.1, Android SDK 35와 Build Tools 35가 필요하다. 먼저 frontend 의존성을 설치한다. `android/scripts/build.ps1`은 Vite 화면, 해시 검증한 별 카탈로그, 모델·라이브러리와 기존 공개 자료를 묶어 APK를 만든다. Gradle/SDK는 한글 경로 제약을 피하도록 별도 ASCII 경로에서 실행한다.

배포 서명 키 `android/astrosky-release.jks`와 `android/signing.properties`는 Git 제외 대상이다. 후속 APK의 동일 서명을 위해 안전하게 보관한다. 새 키로 대체하면 기존 앱 위에 업데이트할 수 없다.

`node --test android/tests/*.test.cjs`는 DEM 값·좌표 보존을, Gradle `testDebugUnitTest`는 후면 카메라 방향·자기편각과 네트워크 제공자 제한을 확인한다. 실제 휴대폰의 자기장 간섭·센서 정확도는 실기기 검증이 필요하다.

## 0.8.0 검증

Android 15 전용 에뮬레이터의 실제 APK/WebView에서 360×800 화면의 모든 도구 버튼, 나침반 방향 적용, 서울 지역 자료 준비, 제주과학고등학교 검색을 확인했다. 같은 실제 DEM/H5와 고정 기상 입력에서 Android WASM과 검증된 Windows 계산 서버가 모두 SQM 15.929, 야간광 픽셀 835개를 반환했다. 기상 입력은 검증용 고정 값이며 새 Meteoblue 조회를 사용하지 않았다. 이 비교는 실행 일치 검증이며 실제 하늘 밝기의 정확도 검증을 대신하지 않는다.

최종 APK는 배포 키의 Android 서명 검증을 통과했다. 다운로드 크기 76,010,708 bytes, SHA-256 `1cc7e735094d5ad8524c7b9fa9a4ab156eb692533a898600be1bd2deed634bf1`. 서명 인증서 SHA-256은 `e5b8e6099682eb248b624e2baa28c2450e6ea8188409db784ecb9f596542c9d9`이다. 실제 제조사별 휴대폰·태블릿 검증은 후속 단계다.

## 앱 내부 업데이트

설정 → 업데이트 확인 → 다운로드 → 업데이트 설치 순서다. 최초 요청 시 Android에서 AstroSky의 앱 설치 허용을 켜고 돌아온다. 마지막 업데이트 확인은 Android 설치 화면에서 사용자가 누른다. 설치 화면을 취소해도 받은 APK를 다음 실행에서 재사용한다.

개발자 저장소의 정식 Latest 릴리스만 조회한다. 버전·정확한 APK 이름·HTTPS 주소·최대 크기를 제한하고 GitHub의 SHA-256 digest, 앱 ID, 증가한 versionCode, 현재 설치 앱과 같은 서명을 모두 검증한다. 검증 실패 파일로 설치 화면을 열지 않는다. API 키나 GitHub 계정은 필요 없다. 공식 자료: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases), [Android PackageManager](https://developer.android.com/reference/android/content/pm/PackageManager).

앱 전용 `cache/app-updates`에는 설치 APK와 메타데이터 한 세트만 보관한다. 중단된 부분 파일은 정리하고, 받은 버전 이상이 설치된 다음 정상 앱 시작 때 적용한 APK·메타데이터를 삭제한다. 장비·기상·배경·지역 자료 폴더에는 이 정리를 적용하지 않는다. 다운로드 실패는 재시도하며 화면을 닫아도 앱이 살아 있는 동안 다운로드를 계속한다.

## 0.8.1 검증과 저장 공간

나침반을 아래 도구막대에 통합했다. 상태 표시줄·내비게이션 버튼·화면 잘림·키보드 여백은 네이티브 창에서 처리해 WebView의 실제 표시 크기를 줄인다. 계산 기준 패널의 접근성 이름을 보정하고 작은 화면에서 숨기지 않는다. Android 15 전용 에뮬레이터에서 세로 화면의 도구 버튼 10개, 계산 기준 펼치기, 나침반과의 겹침 없음, 세 버튼 내비게이션을 둔 가로 화면의 752×336 웹 영역과 업데이트 창 버튼을 확인했다. JavaScript 오류는 없었다.

배포 서명과 동일한 낮은 버전의 검증용 APK에서 실제 공식 0.8.0 APK를 다운로드했다. 해시·패키지·서명 검사, 재실행 뒤 받은 파일 복구, 앱 설치 허용 화면 및 Android 업데이트 확인·설치 완료를 확인했다. 최종 서명된 0.8.1 APK를 같은 앱 위에 설치한 뒤 장비 초점거리 750mm 기록과 기존 지역 파일 해시가 유지되고 적용한 업데이트 캐시가 비는 것을 확인했다. 제조사별 실제 기기 검증은 아직 수행하지 않았다.

최종 APK: 76,018,580 bytes(약 76MB / 72.5MiB), SHA-256 `9581cf6a5577ccdf0ab8897df0e1e11aedf37e81784287e6f4ab58b2cdd91ab4`. 기존 배포 인증서와 같은 SHA-256 서명이다. Android Java 테스트 7개, 공통 기능 테스트 104개, Windows 테스트 24개와 화면 빌드·타입·변경 코드 검사를 통과했다.

Android 15 x86_64 에뮬레이터의 최종 설치 상태에서 디스크 할당량을 측정했다. 앱 본체와 시스템의 컴파일 파일은 78,807,040 bytes, 앱 전용 자료·캐시는 27,582,464 bytes이며 합계 106,389,504 bytes(약 106MB / 101.5MiB)다. 이 상태에는 서울 주변 DEM 2개·Black Marble 1개·타일 목록 14,118,912 bytes(약 14MB), WebView 저장소 약 4.9MB, 일반 캐시 약 8.5MB가 들어 있다. APK에 전 세계 자료를 넣지 않는다. 다른 지역·사용자 배경·사진 캐시를 추가하면 늘어나며 기기별 컴파일 및 캐시 크기도 다르다.

업데이트 다운로드 중에는 현재 APK 크기 약 76MB가 일시적으로 추가되고 Android 설치 작업도 별도 임시 공간을 사용한다. 적용 후 앱 안에 보관한 업데이트 APK는 제거된다. 브라우저의 Downloads에 사용자가 직접 받은 APK는 앱 전용 캐시와 별개다.

## 0.8.2 북쪽 정렬과 방향 안정화

나침반을 켜면 화면 아래에 `북쪽 정렬`·`정렬 초기화`가 나타난다. 후면 카메라를 실제 북극성 방향으로 향한 뒤 정렬하면 현재 원시 방위각을 N(0°) 기준으로 저장한다. 기울기와 높이는 그대로 유지한다. 이 기능은 사용자가 선택한 방향을 북쪽으로 지정하는 수동 방위 보정이며 북극성의 실제 적경·방위각으로 자동 조준하는 기능은 아니다. 천정 바로 위 85° 이상의 방향에서는 방위 정렬을 막는다. 센서가 없는 기기는 손으로 조작한다.

보정값은 고정 WebView 원점의 `astrosky.compass.north-offset.v1`에 저장해 앱 재실행·업데이트 뒤에도 유지한다. 재정렬은 이전 보정 결과가 아닌 원시 센서 방위를 기준으로 하며 초기화는 이 항목만 제거한다. 저장 공간 사용은 숫자 하나 수준이며 지역 자료·장비·기상·배경을 변경하지 않는다.

기존 정규화 선형 보간은 정확히 반대인 두 방향에서 이전 방향에 머무를 수 있었다. 구면 보간과 시간 기반 80ms 평활화로 바꾸고 약 0.15°의 정지 잡음을 억제했다. 회전 벡터는 후면 카메라의 -Z축을 동/북/위 좌표로 변환한다. 화면의 세로·가로 회전만으로 카메라 방향을 다시 매핑하지 않는다. 회전 센서가 없을 때의 가속도·지자기 입력은 100ms 필터를 사용한다.

활성화·복귀 때 센서 등록 시각보다 이전 이벤트와 지난 실행 세대의 메시지는 버린다. 센서→WebView 호출은 한 개만 대기시키며 화면은 최신 방향을 프레임당 한 번 적용한다. 다시 켤 때 이전 보간 상태를 버린다. 2초 동안 새 값이 없으면 정렬을 비활성화하고 기다림을 표시한다. 천체 추적 타이머를 중지해 센서 이동과 충돌하지 않게 하며 하늘 직접 터치·검색 이동은 따라가기를 해제한다.

공통 테스트 109개, Java 테스트 10개, Android 타입·변경 코드 검사와 release 빌드를 통과했다. 전용 Android 15 에뮬레이터의 실제 APK/WebView에 알려진 방향값을 입력해 북↔남 180° 전환, 37° 높이를 유지한 N 정렬, 80° 하늘 기울기, 따라가기 재활성화, 지난 세대 값 무시, 재실행 뒤 정렬 유지, 초기화 및 터치 해제를 확인했다. 세로 360×728·가로 752×336 웹 영역에서 정렬 버튼이 표시 영역 안에 있다. 이는 센서 전달·계산·화면 동작 검증이며 실제 제조사 센서의 자기장 간섭이나 드리프트를 검증한 것은 아니다.

최종 APK는 76,020,368 bytes(약 76MB), SHA-256 `32a5253f91ab292e1047dec710062eda9a0e38e177c38fc755f3c882451c6cd4`다. 기존 배포 인증서와 동일하며 versionCode 802, 최소 Android 8.0이다. 0.8.1 이후 사용자는 앱 설정의 업데이트 확인으로 받으며 Android 설치 최종 확인은 기기에서 진행한다. 실제 기기에서 아래쪽·수평·북극성·천정 방향과 북쪽→남쪽으로 움직인 뒤 재활성화를 추가 확인해야 한다.

## 0.8.3 정렬 창과 Android 최적화

북쪽 정렬은 나침반을 켰을 때 아래 도구막대 위의 작은 버튼으로 표시한다. 버튼을 눌러 안내·현재 방향 정렬·초기화를 열고, 정렬 완료·초기화·닫기 버튼·Android 뒤로가기로 접는다. 창을 닫아도 따라가기는 유지하며 나침반 해제·하늘 직접 터치 때는 버튼과 창을 함께 숨긴다. 저장된 보정값이 있으면 버튼에 체크 표시한다.

가까운 센서 방향은 최근 세 표본을 3차원 벡터로 평균낸 뒤 시간 기반으로 보정한다. 큰 방향 전환은 짧은 평균 창을 즉시 비워 빠르게 따라간다. 정지에 가까우면 220ms, 큰 방향 차이는 60ms로 반응을 조절하고 표시 방향의 변화가 약 0.25° 미만이면 중복 WASM 호출을 생략한다. 내부 값은 계속 누적하므로 느린 실제 이동도 반영한다. 센서 보정은 렌더 프레임 전에 수행하고 최신 보정 방향만 프레임에 전달한다. 360° 경계·천정 방향·180° 전환과 기존 북쪽 보정 저장 방식을 유지한다.

Android에 복사한 Stellarium JS 렌더러만 빌드 시 수정한다. 기존 렌더러는 캔버스의 실제 픽셀 크기를 CSS 크기와 비교해 DPR이 1보다 크면 매 프레임 크기를 다시 설정했다. 실제 픽셀 크기끼리 비교하도록 고치고 최대 30fps로 그린다. 원래 DPR·사진·카탈로그·지도 해상도는 유지하며 배포 원본 JS와 Windows 렌더러는 변경하지 않는다. 원본 렌더 함수가 달라지면 빌드를 실패시켜 수정 누락을 막는다. 센서 상태·정렬 창 변경은 하늘 React 트리를 다시 만들지 않고 Android 도구막대의 배경 흐림 효과도 생략한다.

네이티브 회전 센서는 33,333μs 주기를 요청하고 실제 브리지 전달도 약 30Hz로 제한한다. 전달할 수 없는 이벤트는 행렬 변환 전에 거르며 행렬 배열을 재사용한다. 앱이 백그라운드에 있으면 센서와 WebView 타이머를 멈추고 복귀 때 재개한다. API 동작은 [Android SensorManager](https://developer.android.com/reference/android/hardware/SensorManager), [Android WebView](https://developer.android.com/reference/android/webkit/WebView)를 기준으로 한다.
