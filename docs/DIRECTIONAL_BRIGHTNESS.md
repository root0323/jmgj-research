# 관측 방향에 따른 밤하늘 밝기 코드 확인 · 0.8.5

2026-10-13 현재 코드에서 Black Marble·DEM 연구 모델은 관측 고도·방위각에 따라 다른 결과를 계산한다. 모델 계수·과학 계산 방식은 이번 변경에서 수정하지 않았다.

- `SkyViewer.applySelectedInfo`는 선택한 천체의 고도·방위각을 2° 단위로 묶는다. 장소·관측 시각·방향이 달라지면 저장한 기상 자료를 `evaluateWeather`에 전달해 다시 계산하며 Meteoblue를 새로 조회하지 않는다.
- `frontend/lib/weather-evaluation.ts`는 `/api/research/evaluate` 요청에 고도·방위각을 포함한다. 키는 계산 요청에 포함하지 않는다.
- `difficulty.get_observer_angles`는 고도를 천정각 `90 − 고도`로 바꾸며 `run_pipeline`에 전달한다. 천체 미선택이면 `(천정각 0°, 방위각 0°)`, 즉 천정을 기준으로 계산한다.
- `calculator.run_pipeline`은 관측 천정각·방위각, 야간광 광원 방향, 지형 차폐와 달 방향을 사용한다. 인공광·구름 산란과 달빛 성분은 방향에 따라 달라지며 달빛 산란각에도 `cos(관측 방위 − 달 방위)`가 포함된다.
- Android는 같은 Python `difficulty`·`calculator`를 Pyodide에서 실행한다. `android/model/mobile.py`는 저장 기상 요청을 같은 `CachedWeatherRequest`에 전달한다.

현재 화면은 **선택한 천체 방향**을 기준으로 한다. 천체를 선택한 채 손으로 다른 방향으로 돌려도 선택한 천체의 계산이 유지된다. 화면 가운데 방향을 항상 따라가는 밝기 지도 기능은 구현하지 않았다. 천체 선택이 없으면 천정 기준이다. 입력 기상·지역 자료 부족이나 계산 오류로 간이 추정을 사용하면 위치·운량 중심의 값을 사용하므로 방향별 차이가 반영되지 않는다.

검증: 동일한 고정 시험 입력(단일 북쪽 광원, 맑은 대기·AOD 0.15, 북쪽 고도 45°의 보름달)으로 실제 `run_pipeline`을 실행했다. 관측 고도 45°에서 북쪽·남쪽·동쪽의 SQM은 각각 15.5082·20.9656·20.7545, 북쪽 고도 80°는 20.4422였다. 인공광·달빛 성분도 달라짐을 확인했다. 이는 방향 전달과 수학적 동작 확인용 **가상 시험 조건**이며 실제 서울 예보·측정값·모델 정확도 검증을 뜻하지 않는다. 새 API 요청·계정 크레딧 사용은 없었다.
