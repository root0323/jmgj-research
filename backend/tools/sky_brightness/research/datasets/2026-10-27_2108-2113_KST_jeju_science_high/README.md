# 2026-10-27 제주과학고 북쪽 지도 핀 · SQM-L

사용자가 제공한 실제 관측 구간은 **21:08~21:13 KST**다. 처음 준비 요청의 21:05~21:15보다 관측표를 우선했다.
원본 49칸 중 숫자가 있는 실측 **33개**(고도 30° 11개, 60° 21개, 천정 1개)를 분석했다. `-` **16개**는 원본에 그대로 남겼으며, 0이나 보간값으로 채우지 않았다. 결측 원인은 확인되지 않았다. 별도 이상치 제거는 없다.
장비는 **SQM-L 고정**, 방위각 북쪽 0°·동쪽 90°다. 생략된 시간 칸은 표의 같은 관측 구간을 상속했다.

## 위치와 받은 API

오늘 위치는 운동장 중앙이 아니라 **사용자가 사진과 열린 지도에서 표시한 제주과학고 건물 북쪽의 파란 핀**이다.
[핀 공유 링크](https://kko.to/hwFh2rXa3Y)의 WCONGNAMUL 좌표 `(390872, -18336)`을 WTM(EPSG:5181)으로 바꾸고 위·경도로 변환해 **33.426633°N, 126.530639°E**를 사용했다. 지도에서 고른 지점이며 실제 측정기의 GPS 측량값은 아니다.
[사용자 원본 사진](raw/location_reference_user.png), [변환 근거·좌표](raw/location_reference.json)를 보존했다. 좌표 변환은 카카오 담당자의 [2.5배 관계 설명](https://devtalk.kakao.com/t/wtm/59226)과 [EPSG:5181·변환 예시](https://devtalk.kakao.com/t/topic/38086)에 대조했다.

- 위치 정정 후 새 API를 **10월 27일 21:48:02 KST**에 받았다. 실제 관측 후 수신한 모델 자료이며, 관측 전에 고정한 예보 자료는 아니다.
- `airquality-3h`, `clouds-3h`, `air-3h` 전체 JSON과 수신 기록을 저장했다. 세 패키지의 실제 간격은 **3시간**이며 **10월 27일 21:00~10월 28일 00:00**을 보간했다. 정확한 배열 범위와 시각은 원본에서 확인한다.
- 대표 시각은 분 단위 어댑터에 맞춰 구간 중간 21:10:30을 내림한 **21:10**이다. 개별 방향의 측정 시각은 없다. 21:08·21:13으로 입력 민감도도 계산했다.
- 대표 입력은 AOD550 **0.10056**, 구름 비율 **0.66944**, 대류 구름 밑면 압력 환산 높이 **19.20961km**다. 이것은 현장 대기 실측이나 확인된 전체 구름 밑면 높이가 아니다.
- 위치를 정정하기 전 21:40에 받은 운동장 중앙 자료는 **오늘 평가에 사용하지 않았다**. [사용하지 않은 조회 기록](unused/tamna_playground/README.md)으로 분리했다. 두 위치의 조회 수신 기록을 모두 남겼으며 인증 정보는 제외했다.
- 기존 Black Marble H5와 DEM 파일은 존재와 해시를 확인했고 같은 자료를 재사용했다. 대용량 파일은 중복 업로드하지 않았다.

지난 후보는 오늘 자료에서 기본 모델보다 개선되지 않았다. 오늘 보정의 방향 검증은 기본보다 약 3.6% 낮지만, 전체 보정 오차와 차이가 크고 방향별 큰 잔차가 남는다. 앱 기본값을 바꾸거나 다른 날짜에 일반화가 확인된 것으로 다루지 않았다.

**001_frozen_candidate_evaluation**은 10월 22일 `g=0.5`, `art_scale=0.05`, `moon_cloud_gain=118.24386924943558`을 고정했다. 오늘 실측으로 다시 맞추지 않은 새 날짜 검사다.

**002_scattering_calibration**은 이전과 같은 두 후보 계열과 탐색 범위를 사용했다. 분할 안에서만 계수와 g를 골랐다.

| 후보 계열 | 전체 보정 RMSE | 방향 검증 RMSE | 전체 보정 계수 |
| --- | ---: | ---: | --- |
| 기존 산란 계수 | 1.11813 | **1.31789** | g=0.9, art_scale=1.5, ms_a=1.436802837480366 |
| 경험적 구름·달빛 항 | 1.10446 | 1.94124 | g=0.9, art_scale=2.198701740640679, moon_cloud_gain=0 |

후보 선택은 같은 진단용 방향 검증을 참고했다. 전체 보정 RMSE가 더 낮다는 이유로 구름·달빛 후보를 선택하지 않았다. 선택된 기존 계수의 인공광 배율은 탐색 상한에 걸려 있다.

검증은 방위각 60° 구간 6개와 천정 1개를 번갈아 제외하는 7개 분할이다. 같은 방위 구간의 두 고도는 함께 제외했고, 33개가 정확히 한 번씩 검증에 들어간다. 다만 결측 때문에 한 분할은 유효값 **1개**뿐이다. 분할별 관측 수·ID를 보고 해석해야 한다. 천정은 방위각 그룹에서만 제외한다.
방향 검증 RMSE는 고도 30° **1.45144**(n=11), 60° **1.27506**(n=21), 천정 **0.02856**(n=1)다. n=1의 RMSE는 절대 오차와 같다.

## 밤·달·전이 성능에 관한 한계

- 대표 시각 태양 고도 **−42.71543°**로 천문학적 밤이다. 10월 26일의 국소 황혼 항은 사용하지 않았다.
- 달 고도 **33.24424°**, 방위각 **82.97369°**, 조명 비율 **97.37%**다. 고도 30°·방위각 75°와 90°는 달과 각각 **7.52194° / 6.80364°** 떨어져 있다.
- 제조사 [Unihedron의 SQM-L 사양](https://www.unihedron.com/projects/sqm-l/)은 각도 응답 HWHM 약 10°·FWHM 약 20°를 제시한다. 이것은 딱 잘리는 시야 경계가 아니다. 가까운 두 방향은 직접 달 유입 가능성의 **기하 진단**으로만 표시했다. 실제 달의 노출·구름이나 건물의 차폐·조준 정확도는 확인하지 못했으며 두 실측도 평가에 포함했다.
- 모델은 SQM-L 전체 각도 응답이나 달 원반·직접광의 기기 응답을 적분하지 않는다. 일괄 밝기 계수 조정만으로 이번 방향 패턴을 충분히 설명하지 못했다.
- 오늘 선택한 계수를 10월 22일 자료에 고정해 되돌려 계산하면 RMSE **1.42549**다. 10월 22일 자체 보정 후보의 0.59224보다 크다. 후보 계열의 설계에 10월 22일 자료를 이미 참고했으므로 이 역방향 비교도 완전히 보지 않은 최종 시험은 아니다.
- 오늘 계수를 고정한 시간 민감도 RMSE는 21:08 **1.12262**, 21:10 **1.11813**, 21:13 **1.11280**이다. 실제 5분 사이의 구름·직접광 변화까지 나타내지는 못한다.

10월 22일·27일 야간 자료와 10월 26일 황혼 자료를 구분해 보존한다. 10월 15일 자료는 계속 보관 전용이다. 오늘 선택한 후보와 과거 후보 어느 것도 앱 기본값으로 채택하지 않았다.

## 저장 파일과 재현

- `raw/`: 사용자 SQM 표 49칸, 지도 사진과 핀 좌표 근거, 실제 지점의 API 전체·수신 기록, 메타데이터.
- `inputs/`: 유효 33개 CSV, 세 시각의 환경 스냅샷, 위성광·DEM 해시 확인, 달과의 각거리와 SQM-L 사양 근거.
- `selections/`: 유효·결측 ID, 결측을 채우지 않았다는 기록. `unused/`는 위치 정정 전 조회이며 계산 입력이 아니다.
- 두 실행에 예측·오차·MSE/RMSE·방위각/고도 CSV·PNG·비교 그림·소스/입력/자료 해시를 저장했다. 002에는 두 후보 계열, 모든 분할, 고도 교차 검사, 시간 민감도와 역방향 날짜 진단도 있다.
- 비교 그래프는 15° 순회의 빠진 방향을 선으로 잇지 않는다. 예측 CSV와 오차에는 33개만 포함한다.

저장소 루트에서 `PYTHONPATH=backend/src`와 기존 연구용 Python 환경을 설정한다. Windows에서는 Matplotlib와 임시 폴더를 쓰기 가능한 작업 폴더로 지정한다. API 키나 네트워크 없이 다음과 같이 재현한다. 이미 있는 실행 폴더는 덮어쓰지 않는다.

```text
python backend/tools/sky_brightness/research/evaluate_frozen.py --observations <이 데이터 세트>/inputs/v001_valid_33.csv --cache <이 데이터 세트>/raw/weather_cache_33.426633_126.530639_2026-10-27.json --params backend/tools/sky_brightness/research/datasets/2026-10-22_2123-2218_KST_jeju/runs/002_scattering_calibration/candidate_params.json --h5 <H5> --dem <DEM> --output <새 평가 폴더>
python backend/tools/sky_brightness/research/calibrate_scattering.py --observations <이 데이터 세트>/inputs/v001_valid_33.csv --cache <이 데이터 세트>/raw/weather_cache_33.426633_126.530639_2026-10-27.json --h5 <H5> --dem <DEM> --output <새 보정 폴더>
```

역방향 날짜 진단은 보존한 10월 22일 `scattering_components.csv`의 해당 g에서 인공광 항에 art_scale을 곱하고, 전체 휘도에 `(새 ms_a + ms_b*AOD)/(기본 ms_a + ms_b*AOD)`를 곱해 계산했다. 같은 재조합이 오늘 직접 파이프라인 예측과 1e-10 이내에서 일치함을 확인했다. 원본 성분·관측 해시는 `cross_date_diagnostic.json`에 있다.
정확한 결과는 실행별 JSON/CSV에서 조회하고 [전체 결과 목록](../../RESULTS.md)과 [색인](../../index.json)을 함께 사용한다.
