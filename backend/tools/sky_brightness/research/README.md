## 저장 구조

- `datasets/<관측 ID>/raw/`: 사용자가 제공한 원본 SQM 표와 API JSON 전체. 천정 표기와 제외된 값도 보존한다.
- `inputs/`: 시간대·단위를 명시한 모델 입력과 해당 시각 API 발췌본.
- `selections/`: 포함/제외 여부, 이유, 사용자 정정 내용을 원본과 별도로 관리한다.
- `runs/<실행 번호>/`: 같은 관측 선택으로 계산한 기본값·보정 후보·방향별 오차·검증·그래프.
- `models/<소스 커밋>/`: 계산식과 계수, 연구용 입력 어댑터, 원래 앱 어댑터 및 파일 해시.
- `index.json`, `CHANGELOG.md`: 자료와 실행의 목록 및 변경 이유.

## 이전 1시간 API JSON 원본 복원 (보관 자료)

원본 파일은 6,915,435 bytes이며 압축 전후 내용은 동일하다. API 키·인증 헤더는 들어 있지 않다.
다음 명령은 압축 파일을 유지하면서 원본 JSON을 복원한다.

```python
import gzip
from pathlib import Path
source = Path("datasets/2026-10-15_0000_KST_jeju/raw/weather_cache_33.4268_126.5303.json.gz")
source.with_suffix("").write_bytes(gzip.decompress(source.read_bytes()))
```

SHA-256은 `raw/metadata.json`의 `raw_api_original_sha256`과 대조한다.
관측은 한국시간이며 API 원본은 UTC다. 해당 관측은 UTC **2026-10-14 15:00**과 연결했다.
API 자료가 관측 이후 생성되어 이번 결과는 과거 재현 비교이며 실시간 예보 성능 검증이 아니다.

## 이전 1시간 자료의 전체 계산 재현

기존 연구 환경의 `numpy`, `rasterio`, `numba`, `h5py`를 사용한다. `--h5`, `--dem`에는 보존한 해시와 일치하는 실제 자료 경로를 지정한다.
대용량 위성광·DEM은 저장소에 중복해서 올리지 않는다. 사용한 두 파일의 해시는 각 `comparison.json`에 있다.

```text
python recompute_physics.py --observations datasets/2026-10-15_0000_KST_jeju/inputs/v002_unobstructed_21.csv --cache datasets/2026-10-15_0000_KST_jeju/inputs/api_snapshot_2026-10-14_1500_UTC.json --h5 <위성광파일> --dem <지형파일> --max-pixels 1000 --output <새결과폴더>
```

명시한 고정 기상 파일만 사용하며 Meteoblue 유료 조회나 기존 기상 캐시 변경은 하지 않는다.
모델 스냅샷의 `data_loader.py`는 시간대 오류를 바로잡은 연구 전용 어댑터다. 앱의 최신 기상·저장·다운로드 코드를 대체하지 않는다.

## 매번 추가할 내용

1. 원본 실측·API 파일을 보존하고 시각·시간대·위치·관측 방향·단위·측정기 정보를 기록한다. 누락된 정보는 추정해서 채우지 않는다.
2. 건물·직접광·차폐·결측 등의 품질 정보는 별도 선택 버전으로 기록한다.
3. 모델 소스 커밋·계수·입력 처리·위성광/DEM 해시·픽셀 수·반경을 실행 기록에 고정한다.
4. 같은 평가 자료에서 기본 모델과 후보를 비교한다. 보정에 사용한 자료와 검증 자료를 구분한다.
5. 후보·검증 통과·앱 반영 상태를 구분한다. 한 시각의 방향 구간 검증을 다른 날짜 검증으로 표현하지 않는다.
6. 새 실행 번호와 변경 이유를 추가하고 GitHub에 커밋한다. 앱에 실제 채택할 때는 별도로 앱 빌드·검증·배포 절차를 따른다.
