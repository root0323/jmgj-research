## 나중에 질문받았을 때 읽는 순서

1. 관측 날짜가 KST인지 UTC인지 확인하고 위 목록과 `index.json`에서 데이터 세트·실행 번호를 찾는다.
2. 해당 데이터 세트의 `raw/metadata.json`, `selections/`, `inputs/`로 위치·장비·시각·제외 기준·API를 확인한다.
3. 실행의 `report.json`, `comparison.json` 또는 `metrics.json`으로 정확한 지표·계수·검증 방식을 확인한다. 비교할 때 픽셀 수와 자료 선택 조건을 맞춘다.
4. 개별 방향 질문은 예측 CSV와 각도별 오차 CSV, 그래프 질문은 저장된 PNG를 확인한다. 이미 보존한 결과를 설명하기 위해 API를 새로 조회할 필요는 없다.
5. 최신 결과를 이전 실행의 결과처럼 답하지 않는다. 저장되지 않은 값이나 미실행 검증은 없다고 명확히 답한다.

## 데이터를 받을 때마다 남길 것

원본 실측, 사용 API(자격 증명 제외), 단위·시간대·장소·장비·관측 구간, 포함/제외 기준, 모델 소스·계수·자료 해시·계산 조건, 기본/후보/검증 지표와 예측표, 방위각·고도별 RMSE 및 비교 그래프, 해석·한계·앱 적용 여부를 새 데이터 세트/실행에 보존한다.
모델이 개선되지 않거나 API가 없어 계산을 보류해도 원본과 가능한 분석을 저장하고, 미계산 항목과 그 이유를 기록한다. 결과 목록·색인·변경 기록을 함께 갱신하고 GitHub origin에 보존한다.
